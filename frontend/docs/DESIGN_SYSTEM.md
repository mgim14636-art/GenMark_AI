# GenMark AI 화면 디자인 명세

> 상태: 제안 v1.0  
> 기준 화면: 현재 구현된 Hero 화면  
> 적용 범위: Hero를 제외한 로그인·온보딩·생성·분석·결과·마이페이지·설문 화면

## 1. 디자인 읽기

GenMark AI를 **브랜드를 만드는 과정을 보여주는 크리에이티브 스튜디오형 SaaS**로 정의한다.
현재 Hero의 핵심은 넓은 여백, 중앙의 짧은 메시지, 선명한 인디고 CTA, 작업물을 전면에 내세운 이미지 갤러리다.
나머지 화면도 같은 언어를 사용하되, 작업 단계에서는 장식보다 **읽기 쉬운 구조와 다음 행동의 명확성**을 우선한다.

- 무드: editorial gallery / quiet confidence / modern brand studio
- 디자인 변주: 7/10 — 대칭을 기본으로 하되 결과물과 이미지에서 비대칭을 허용
- 모션 강도: 5/10 — 화면 전환과 생성 진행을 설명하는 정도의 모션
- 시각 밀도: 4/10 — 한 화면에 하나의 핵심 질문과 하나의 주요 행동
- Hero는 현재 상태를 유지한다. 이 문서의 규칙은 Hero의 톤을 나머지 화면에 확장하는 기준이다.

### 1.1 Hero와 앱 화면의 구분

Hero는 서비스의 첫인상을 만드는 **마케팅/소개 화면**이고, Hero를 제외한 모든 화면은 사용자가 실제로 작업하는 **앱 화면**이다.
두 영역은 같은 색·타이포그래피·브랜드 언어를 공유하지만, 목적과 레이아웃은 분리한다.

| 영역 | Hero | 나머지 화면(App) |
| --- | --- | --- |
| 목적 | 서비스의 가치와 분위기 전달 | 생성·검토·수정 작업 완료 |
| 레이아웃 | 이미지가 주도하는 넓은 캔버스 | 헤더·콘텐츠·상태·내비게이션이 있는 작업대 |
| 정보량 | 적게, 한 메시지 중심 | 단계와 입력값을 명확하게 |
| CTA | 서비스 시작 유도 | 현재 작업을 완료하는 기능 행동 |
| 모션 | 갤러리·스크롤 중심 | 진행 상태·선택·화면 전환 중심 |

앱 화면에는 다음 규칙을 반드시 적용한다.

- 화면 상단에는 현재 서비스 맥락을 알려주는 앱 헤더를 둔다.
- 콘텐츠 폭과 여백을 일정하게 유지해 사용자가 “다음에 무엇을 해야 하는지” 바로 이해하게 한다.
- Hero의 이미지 갤러리 효과, 장식용 대형 여백, 마케팅 문구를 앱 화면 전체에 복제하지 않는다.
- 모든 화면은 로딩·오류·빈 상태·완료 상태를 포함한 기능 화면으로 설계한다.
- 화면의 주인공은 UI 장식이 아니라 사용자가 만든 로고와 그에 대한 검토 결과다.

## 1.2 GenMark-AI 브랜드 가이드라인

GenMark-AI는 창의적인 제작 경험과 신뢰할 수 있는 검토 기능 사이에 위치한다.

| 구분 | GenMark-AI 방향 |
| --- | --- |
| 핵심 인상 | 전문적, 감각적, 신뢰감 있는 |
| 사용자에게 주는 느낌 | 어렵지 않다, 안심된다, 결과가 정돈되어 있다 |
| 브랜드 성격 | 차분한 전문가, 친절한 컨설턴트 |
| 디자인 분위기 | 미니멀, 깨끗함, 절제된 세련미 |
| 피해야 할 이미지 | 지나치게 화려함, 장난스러움, 차가운 기술 서비스 |
| 화면의 주인공 | 서비스 UI가 아니라 사용자가 만든 로고 |
| 핵심 메시지 | 생성과 검토를 한 번에 제공 |

### 우리가 아닌 이미지

- 감각만 앞세우는 자유로운 예술가
- 어려운 용어만 사용하는 상표 전문 변호사
- 화려한 결과만 보여주는 이미지 생성 도구
- 숫자와 분석만 보여주는 딱딱한 데이터 서비스

GenMark-AI는 다음 세 요소의 중간 지점에 있어야 한다.

> 예술가의 창의성 + 컨설턴트의 전문성 + 분석 도구의 신뢰성

따라서 화면 문구는 전문 용어를 그대로 노출하지 않고 쉬운 말로 설명하며, 결과 화면은 감성적인 결과물과 객관적인 검토 정보를 같은 위계 안에서 보여준다.

### 서비스 이미지와 문구 원칙

- 전문성은 복잡한 용어가 아니라 정돈된 정보 구조와 예측 가능한 흐름으로 전달한다.
- 친절함은 과한 캐릭터나 장난스러운 일러스트가 아니라 짧고 구체적인 도움말로 전달한다.
- 감각은 장식의 양이 아니라 결과물 프리뷰의 품질, 여백, 타이포그래피의 절제로 표현한다.
- 분석 신뢰성은 숫자를 크게 보여주는 것보다 상태의 의미·근거·한계를 함께 설명하는 방식으로 표현한다.
- “생성”과 “검토”가 별도 제품처럼 보이지 않도록 단계 전환과 결과 화면에서 하나의 작업 흐름으로 연결한다.

## 2. 공통 디자인 토큰

### 2.1 색상

색상은 한 화면 안에서 인디고를 단일 액센트로 고정한다. 핑크·라일락은 장식이 아니라 상태나 이미지 보정에만 사용한다.

```css
--color-canvas: #ffffff;
--color-canvas-soft: #f8f8fc;
--color-ink: #111217;
--color-ink-soft: #555866;
--color-ink-muted: #858792;
--color-accent: #4b43d6;
--color-accent-strong: #3931b8;
--color-accent-soft: #eeedff;
--color-line: #e8e8ef;
--color-success: #2f8f69;
--color-warning: #b86b2b;
--color-danger: #c94862;
--color-kakao: #fee500;
```

- 기본 배경은 순백색, 보조 영역은 `--color-canvas-soft`를 사용한다.
- 배경 전체를 보라색 그라디언트로 채우지 않는다.
- CTA는 기본적으로 `--color-accent` 단색이다. 그라디언트는 생성 완료 배지나 아주 약한 배경 광원에만 허용한다.
- 본문 텍스트 대비는 WCAG AA(4.5:1 이상)를 만족한다.

#### 색상 의미 체계

서비스가 다양한 브랜드의 로고를 보여줘야 하므로 메인 UI 색상은 낮은 채도와 넓은 흰색 여백을 유지한다.

| 의미 | 역할 | 권장 계열 | 사용 위치 |
| --- | --- | --- | --- |
| 창의성 | 메인 액센트 | 차분한 보라색·인디고·블루 | 주요 CTA, 선택 상태, 진행 강조 |
| 신뢰감 | 구조와 텍스트 | 딥 네이비 | 제목, 헤더, 결과 설명, 아이콘 |
| 안정감·친근함 | 바탕과 보조 영역 | 흰색·아주 밝은 회색·부드러운 베이지 | 캔버스, 카드, 입력 영역 |
| 성공·낮은 유사도 | 안전 상태 | 초록색 | 안전, 분석 완료, 낮은 유사도 |
| 주의·중간 유사도 | 확인 필요 상태 | 주황색 | 추가 확인, 중간 유사도 |
| 위험·높은 유사도 | 경고 상태 | 빨간색 | 높은 유사도, 오류, 위험 안내 |

- 상태 색상은 배경 전체가 아니라 badge·아이콘·짧은 라벨에 제한한다.
- 초록·주황·빨강은 브랜드 액센트가 아니며, 상표 분석 상태에서만 의미를 갖는다.
- 같은 상태를 색상, 아이콘, 텍스트 세 가지로 함께 표현한다.
- 사용자의 로고 색과 충돌하지 않도록 결과물 프리뷰 주변에는 컬러 장식을 최소화한다.

### 2.2 타이포그래피

- 모든 한글 UI: `Pretendard, Pretendard Variable, sans-serif`
- 영문 로고·작업물 이름: 화면별 브랜드 미리보기에서만 별도 표시체를 허용한다.
- 제목: 700~800, `letter-spacing: -0.06em ~ -0.09em`, `line-height: 1.18~1.35`
- 본문: 400~500, 15~18px, `line-height: 1.55~1.7`
- 보조 문구: 12~14px, 색상은 `--color-ink-muted`
- 제목 안에서 강조할 때는 다른 폰트가 아니라 같은 폰트의 굵기와 `--color-accent`로 처리한다.

권장 크기:

| 역할 | Desktop | Mobile |
| --- | ---: | ---: |
| 화면 제목 | 44~56px | 30~38px |
| 섹션 제목 | 24~32px | 20~24px |
| 카드 제목 | 18~22px | 16~19px |
| 본문 | 16~18px | 14~16px |
| 보조 | 12~14px | 12~13px |

### 2.3 모양·간격

- 페이지 컨테이너: `width: min(calc(100% - 48px), 1120px)`
- 모바일 컨테이너: 좌우 16px
- 기본 간격 단위: 8px (`8 / 16 / 24 / 32 / 48 / 64`)
- 컨트롤 모서리: 8px
- 카드 모서리: 16px
- 결과물 프리뷰 모서리: 20~24px
- 상태 배지와 진행 단계: pill(999px)
- 그림자: `0 12px 32px rgb(42 35 105 / .08)`처럼 배경에 색을 섞고, 검은 그림자는 사용하지 않는다.
- 아이콘: 프로젝트에 이미 사용 중인 Lucide를 유지하고 `strokeWidth: 1.8`을 기본값으로 한다. 아이콘만으로 의미를 전달하지 말고 라벨 또는 `aria-label`을 함께 제공한다.

## 3. 공통 레이아웃

### 3.1 헤더

- 좌측: GenMark AI 워드마크
- 우측: 도움말 아이콘, 로그인/로그아웃 또는 현재 단계
- 높이: Desktop 72~80px, Mobile 60~68px
- 배경: 투명 또는 흰색 `rgb(255 255 255 / .88)`, 하단 1px 라인
- 작업 화면에서는 헤더보다 콘텐츠가 먼저 읽혀야 하므로 로고 크기를 과도하게 키우지 않는다.

### 3.2 하단 내비게이션

현재 구현된 Home / 마이페이지 구조를 유지한다.

- 모바일에서는 화면 하단 safe-area를 포함해 고정한다.
- 아이콘 26px, 터치 영역 최소 44px
- 활성 상태는 인디고 아이콘 + 짧은 라벨로 표현한다.
- 생성 중·로그인·Hero에서는 내비게이션을 숨긴다.

### 3.3 뒤로가기

모든 단계형 화면의 동일한 위치에 배치한다. 브라우저 뒤로가기와 앱 내부 뒤로가기가 같은 단계로 이동해야 한다.

- 좌상단 원형 버튼, 42px 이상
- `ChevronLeft` 사용
- hover/active는 색상과 1px 이동만 사용
- 완료된 결과에서 이전 입력 화면으로 이동할 때 데이터가 사라지지 않아야 한다.

## 4. 화면별 디자인 명세

라우트/상태명은 현재 `App.tsx`의 `ViewMode`를 기준으로 한다.

### 4.1 `login` — 로그인

목표는 회원가입 설명이 아니라 **작업을 이어갈 수 있다는 신뢰**를 주는 것이다.

- 흰색 캔버스, 상단 얇은 헤더, 중앙 정렬 콘텐츠
- Hero의 인디고를 로그인 스탬프 이미지와 CTA에 연결한다.
- 제목은 2줄 이내, 설명은 최대 2줄로 제한한다.
- 카카오 버튼은 카카오 브랜드 노랑을 유지하되 텍스트 대비를 확보한다.
- Google 버튼은 흰색 바탕 + `--color-line` 테두리 + Google 로고를 사용한다.
- 두 버튼 높이는 동일하게 52~56px, 간격은 12px
- 설정/네트워크 오류는 버튼 위 인라인 알림으로 표시한다. 오류 문구만으로 화면 레이아웃이 밀리지 않게 한다.
- `나중에 할게요`는 보조 텍스트 링크로 두며, 주요 CTA처럼 보이게 만들지 않는다.

### 4.2 `onboarding` — 사용 목적과 대상

한 번에 하나의 질문을 보여주는 2단계 설문이다.

- 상단에 `1 / 2`, `2 / 2` 진행 표시와 얇은 progress line
- 질문 제목은 좌측 정렬, 설명은 한 문장
- 선택 카드는 3~4개 그리드. 각 카드에는 작은 일러스트, 제목, 설명, 선택 상태가 함께 있다.
- 선택 상태: 인디고 1px 테두리 + 아주 옅은 인디고 배경 + 체크 아이콘
- 카드 전체가 버튼이며, 터치 영역은 최소 44px
- 복수 선택 단계에는 “여러 개 선택 가능”, 단일 선택 단계에는 “하나만 선택 가능”을 제목 아래에 표시한다.
- 다음 버튼은 하단 고정이 아니라 콘텐츠 뒤에 두어 키보드/스크롤 흐름을 방해하지 않는다.

### 4.3 `brand-details`, `company-details` — 브랜드 설명 입력

입력과 브랜드 미리보기를 병렬로 놓는 **작업대(workbench)** 화면이다.

- Desktop: 좌측 55% 입력, 우측 45% 미리보기. Mobile: 입력 → 미리보기 순서
- 필드마다 항상 보이는 label, 짧은 helper text, 오류 문구를 사용한다.
- 텍스트 영역은 placeholder에 질문 전체를 넣지 말고 실제 label을 유지한다.
- 핵심가치 칩과 태그는 선택 전/후 대비를 분명하게 한다.
- 미리보기는 카드 안에서 결과의 분위기만 보여주는 조용한 캔버스이며, 실제 로고처럼 과장하지 않는다.
- 다음 버튼 문구는 “계속하기”처럼 현재 단계가 드러나는 동사로 통일한다.

### 4.4 `choice` — CI / BI 선택

두 선택지를 단순 비교할 수 있도록 한다.

- 2열 비교 카드, Mobile에서는 세로 스택
- CI/BI 라벨, 사용 상황, 추천 대상, 작은 예시를 같은 위치에 배치
- 추천 항목에는 인디고 outline과 `추천` pill을 표시한다. 색상만으로 추천을 전달하지 않는다.
- 선택 후 화면 하단에 선택 요약을 고정하지 말고 카드 자체를 강조한다.

### 4.5 `tone` — 톤앤매너·색상

Hero의 이미지 갤러리처럼 **색상 자체가 선택 경험**이 되도록 한다.

- 톤 카드는 5개 이하의 큰 컬러 필드 + 이름 + 한 줄 설명
- 색상 견본은 인디고·라일락 계열을 기본으로 하되 모든 카드가 같은 보라색으로 보이지 않게 명도/채도를 분리한다.
- 직접 색상 입력은 기본 선택지를 누른 뒤 펼쳐지는 progressive disclosure로 처리한다.
- 색상 대비를 숫자만으로 설명하지 말고 “차분한 / 전문적인 / 따뜻한” 언어로 함께 설명한다.
- 선택 상태는 2px 인디고 테두리 + 우측 상단 체크로 표시한다.

### 4.6 `style` — 로고 형태 선택

결과물 중심의 갤러리 화면으로 구성한다.

- 4개 이하의 로고 스타일 카드를 2×2 그리드로 배치
- 각 카드는 넓은 흰색/연회색 프리뷰 영역과 짧은 이름·설명을 포함한다.
- 카드를 hover했을 때만 과도한 확대를 사용하지 않고, 2px 이동과 테두리 변화만 사용한다.
- 추천 조합형에는 작은 추천 badge를 표시한다.
- 화면 하단 CTA는 한 개만 강조한다.

### 4.7 `final` — 생성 요청 검토

생성 직전의 불안을 줄이는 확인 화면이다.

- 상단에 “입력 내용을 확인해주세요”라는 짧은 제목
- 브랜드명·유형·톤·스타일·추가 요청을 5개의 summary row로 보여준다.
- 각 row 우측에 `수정` 텍스트 버튼을 둔다. 수정은 해당 단계로 이동해 입력값을 보존한다.
- 주요 CTA: 인디고 단색의 “로고 생성하기”
- 설명 문구로 예상 소요 시간과 생성 횟수/크레딧을 CTA 근처에 명시한다.

### 4.8 `loading`, `trademark-loading` — 생성/분석 진행

빈 화면과 스피너만 보여주지 않는다. 사용자가 지금 무엇이 진행 중인지 이해할 수 있어야 한다.

- 중앙 콘텐츠 + 단계 리스트(완료/진행 중/대기)
- 진행 중 단계는 인디고 ring 또는 짧은 shimmer, 완료 단계는 체크 아이콘
- 로고 생성은 브랜드 키워드·색상·형태가 조합되는 짧은 문장으로 진행 상태를 설명한다.
- 상표 분석은 “유사 이미지 수집 → 특징 비교 → 안전 범위 계산” 순서로 보여준다.
- `prefers-reduced-motion`에서는 애니메이션을 정지하고 상태 텍스트와 progress만 유지한다.

### 4.9 `trademark-selection` — 상표 분석 선택

분석의 가치와 한계를 먼저 설명한 뒤 선택하게 한다.

- 상단 hero icon은 ShieldCheck + Search 조합의 Lucide 아이콘으로 통일한다.
- 혜택 3개는 큰 카드 하나 안의 구분선 리스트로 배치한다.
- “분석하기”는 주요 CTA, “건너뛰기”는 outline 보조 CTA
- 결과가 법적 등록 가능성을 보장하지 않는다는 disclaimer를 버튼 아래에 배치한다.

### 4.10 `trademark-result` — 유사도 분석 결과

숫자보다 판단을 먼저 읽게 한다.

- 상단 summary: 현재 로고, 안전/주의 상태, 유사도 점수
- 상태는 아이콘 + 텍스트 + 색상으로 3중 표현한다.
- 유사 결과는 순위, 썸네일, 브랜드명, 유사도, 유사 이유를 한 row에 배치한다.
- 점수는 큰 숫자로 보여주되, “법률 자문이 아님” 안내를 항상 가까이 둔다.
- 주요 CTA: 결과 화면으로 돌아가기 / 보조 CTA: 다시 분석하기

### 4.11 `result` — 로고 결과

GenMark AI의 핵심 산출물 화면이다. 결과물을 가장 크게 보여주고 설명은 그 다음에 둔다.

- Desktop: 중앙 로고 프리뷰 + 좌우 후보 이동, 아래에 상세 설명
- Mobile: 후보 프리뷰 → 점/페이지네이션 → 설명 → CTA 순서
- 프리뷰 캔버스는 흰색, 미세한 인디고 그림자, 과도한 그라디언트 금지
- 완료 상태는 pill badge로 짧게 표시한다.
- 주요 CTA는 “브랜드 키트 만들기”, 보조 CTA는 “색상·글씨체 수정”
- 다운로드·상표 분석·다시 생성은 utility grid로 분리해 주요 CTA보다 시각적 무게를 낮춘다.

### 4.12 `edit` — 로고 편집기

결과물 편집은 도구처럼 명확해야 하며, 마케팅 화면처럼 장식하지 않는다.

- Desktop: 좌측 큰 artboard, 우측 controls panel
- Mobile: artboard 위, 탭(심볼/글씨/배치) 아래
- 선택된 객체에는 1px 인디고 bounding box와 최소한의 핸들을 표시한다.
- 슬라이더는 label + 현재 값 + reset을 같은 줄에 둔다.
- “수정 적용하기”는 sticky primary CTA, 상표 재분석은 secondary CTA
- 자동 저장 상태는 헤더의 작은 텍스트로만 보여준다.

### 4.13 `mypage` — 작업 보관함

마케팅 랜딩이 아니라 사용자의 작업을 빠르게 이어가는 워크스페이스다.

- 상단 제목 아래 첫 섹션은 “이어서 만들기” 한 개만 크게 노출한다.
- 완료 프로젝트는 결과 썸네일, 상태, 최근 작업, 2~3개의 핵심 액션을 제공한다.
- 프로젝트가 없을 때는 빈 상태 설명 + 바로 시작 버튼을 함께 보여준다.
- 카드 수가 늘어나면 장식용 그림자보다 구분선과 정보 계층을 우선한다.

### 4.14 `survey` — 만족도 설문

사용자에게 평가를 요구하는 화면이 아니라 다음 개선점을 듣는 대화형 폼으로 표현한다.

- 질문마다 한 문장 helper text
- 평가는 Like/Dislike 두 개의 큰 선택 버튼으로, 색상만이 아니라 아이콘과 텍스트를 함께 사용한다.
- 개선 항목은 3열 칩 그리드, Mobile에서는 2열
- 자유 입력은 항상 label을 제공하고 글자 수를 표시한다.
- 제출 후에는 성공 아이콘 + 짧은 감사 문구 + 마이페이지 돌아가기만 보여준다.

## 5. 인터랙션·모션 규칙

- 기본 transition: 160~220ms, `cubic-bezier(.16, 1, .3, 1)`
- 화면 진입: opacity 0→1 + y 12px, 280~360ms
- 카드 선택: border/color 전환 + scale 0.99 이하. 레이아웃 크기를 움직이지 않는다.
- 생성 진행: 300~450ms stagger를 사용하되 반복 루프는 피한다.
- 버튼 active: `translateY(1px)` 또는 `scale(.98)`
- hover에만 의존하지 않는다. 모든 상태는 focus-visible과 active에서도 확인 가능해야 한다.
- `prefers-reduced-motion: reduce`에서 화면 전환·shimmer·자동 이동을 제거한다.

## 6. 반응형 기준

| 구간 | 기준 |
| --- | --- |
| 375~639px | 1열, 좌우 16px, 버튼 full-width, 하단 nav 표시 |
| 640~1023px | 1~2열, 좌우 24px, 카드 간격 16px |
| 1024~1439px | 작업대 2열, 컨테이너 960~1120px |
| 1440px 이상 | 컨테이너 최대 1120px, 결과 프리뷰만 확장 |

- 가로 스크롤은 허용하지 않는다.
- 모든 주요 버튼과 아이콘 버튼은 최소 44×44px이다.
- 모바일에서 긴 제목은 2~3줄까지 허용하되 버튼 텍스트는 줄바꿈하지 않는다.
- 입력 포커스 시 브라우저 확대가 일어나지 않도록 모바일 입력 글자 크기를 16px 이상으로 유지한다.

## 7. 접근성·상태 체크리스트

- 모든 화면에 `h1` 하나와 논리적인 heading 순서가 있다.
- 아이콘 버튼에는 `aria-label`, 이미지에는 의미에 맞는 alt 또는 빈 alt를 제공한다.
- 오류는 해당 입력/버튼 가까이에 표시하고 `role="alert"`를 사용한다.
- 로딩 상태는 `aria-live="polite"`로 알리고, 완료 상태는 텍스트로도 전달한다.
- 키보드 focus ring을 제거하지 않는다.
- 선택/완료/위험 상태는 색상만으로 구분하지 않는다.
- 375px, 768px, 1024px, 1440px에서 레이아웃을 확인한다.

## 8. 구현 우선순위

1. 공통 토큰·헤더·뒤로가기·버튼 상태 통일
2. 온보딩과 입력 화면의 질문/선택 구조 통일
3. 생성·상표 분석 로딩 상태의 진행 정보 개선
4. 결과·편집기에서 결과물 중심 레이아웃 적용
5. 마이페이지·설문에 동일한 작업대 톤 적용
6. 각 화면의 모바일·키보드·오류 상태 QA

## 9. 최종 방향 요약

### 서비스 차별점

AI 로고 생성과 기존 상표 이미지 유사도 분석을 한 번에 제공한다.

### 서비스 이미지

창의적인 로고 제작과 신뢰할 수 있는 검토를 함께 제공하는 전문적인 브랜드 파트너다.

### 이미지 키워드

전문적, 감각적, 신뢰감, 차분함, 친절함, 정돈됨

### 색상 방향

화이트 기반의 미니멀한 앱 화면에 보라색과 네이비를 사용하고, 유사도 결과는 초록·주황·빨강으로 명확하게 구분한다.

### 디자인 원칙

서비스 자체보다 사용자가 생성한 로고가 더 돋보이게 한다.

### 기획서용 한 문장

> GenMark-AI는 감각적인 로고 제작 경험과 신뢰할 수 있는 상표 이미지 유사도 분석을 함께 제공하는, 전문적이고 친근한 브랜드 제작 서비스의 이미지를 지향한다.

## 10. 금지 사항

- Hero와 무관한 새 네온 컬러 또는 화면별 보라색 변형 추가
- 모든 영역을 둥근 카드와 그림자로 감싸기
- 스피너 하나만 있는 로딩 화면
- placeholder만 있는 입력 필드
- hover에서만 보이는 핵심 기능
- 확인되지 않은 상태를 초록색 성공으로 표시
- Hero의 이미지 갤러리 효과를 입력/결과 화면 전체에 복제하기
