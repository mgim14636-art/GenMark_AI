## 1. 점수 대역이 올라갔다

로고 생성 방식이 바뀌면서 같은 "무관한 로고"의 점수가 달라졌다.

| 로고 형식 | 최고 유사도 |
|---|---|
| 심볼 단독 (이전 측정) | 21.0 · 19.4 |
| 텍스트 결합 (2026-08-12) | 23 · 35 · 50 · 59 |

### 원인

`COS_ANCHORS`의 기준점이 심볼 단독 로고로 잡혀 있다.

```python
# similarity_service.py
COS_ANCHORS = ((0.42, 0.0), (0.80, 30.0), (0.89, 60.0), (1.00, 100.0))
#                            ^^^^ 생성 로고 top-1 코사인 p95 (2026-08-10 측정)
```

KIPRIS 데이터셋은 전부 도형복합(도형+문자) 상표다. 쿼리도 텍스트가 결합되면
형식이 맞아떨어져 코사인이 전반적으로 높아진다. 눈금은 그대로인데 입력만
바뀌어, **무관한 로고 4장 중 3장이 MODERATE로 표시**된다.

### 영향

과잉 경고다. 다 위험하다고 표시하면 사용자가 표시를 신뢰하지 않게 되고,
정작 위험한 건이 묻힌다.

다만 위험한 것을 SAFE로 놓치는 방향은 아니므로, 서비스 안전성 관점에서
급한 결함은 아니다.

### 대응 (보류)

`scripts/calibrate_score.py`로 앵커를 재산출한다. 지금 하지 않는 이유:

- 새 형식 로고 표본이 4장뿐이다. p95를 잡으려면 30장 이상 필요하다 (약 $2.4)
- `app/` 아래 프롬프트 이관(brief_service)이 끝나면 로고 형식이 다시 조정될
  수 있다. 지금 보정하면 두 번 일하게 된다

**순서**: 프롬프트 이관 완료 → 확정 파이프라인으로 30장 생성 → 재보정 → 구간 검증

## 2. 점수가 도형이 아니라 레이아웃에 좌우된다

### 실측

`logo_4` (얇은 초승달 + 한글, 남색) — **59점 MODERATE**

| 순위 | 상표 | 점수 | 도형 |
|---|---|---|---|
| 1 | 케이클리어 | 59 | K 형태 |
| 2 | 밝음나눔 | 59 | 물방울 |
| 3 | 글로우 더 스킨 | 57 | S 형태 |

세 건 모두 **심볼 위 · 한글 아래**, 얇은 선, 남색·검정 계열로 레이아웃과
스타일이 같다. 그러나 **도형은 초승달과 무관하다.**

반대로 `logo_1` (굵은 초승달 + 한글, 파랑) — 23점 SAFE. 3위로 걸린
`정읍사 달빛 사랑숲`은 **실제로 초승달이 들어 있는데 22점**이다.

> 도형이 같은데 점수가 낮고, 도형이 다른데 점수가 높다.

### 원인 (추정)

DINOv2는 이미지 전체를 768차원 벡터 하나로 만든다. 텍스트가 결합된 로고는
면적의 상당 부분이 글자라, 글자 배치·굵기·여백이 임베딩을 지배하고 도형은
일부에 그친다.

상표 유사 판단의 핵심은 도형의 유사성인데, 현재는 전체 인상의 유사성을 재고 있다.

## 3. 심볼 크롭 — 검증 후 기각

### 가설

글자를 빼고 심볼만 조회하면 도형 유사도가 드러날 것이다.

### 방법

행별 잉크 픽셀 수로 심볼과 글자 사이의 빈 띠를 찾아 크롭하고, 정사각 흰
배경에 배치해 재조회했다. 같은 로고를 전체/심볼 두 번 조회해 비교했다.

### 결과 — 더 나빠졌다

| 로고 | 전체 조회 | 심볼만 |
|---|---|---|
| logo_1 | 23 | 22 |
| logo_2 | 35 | 29 |
| logo_3 | 50 | 26 |
| logo_4 | 59 | 31 |

점수만 내려간 것이 아니라 매칭 대상이 더 엉뚱해졌다. 심볼 조회 결과는
`"S"`, `"O"`, `"C"`, `"AE"`, `"Y"` 등 **글자 하나짜리 상표**로 채워졌다.

결정적으로, 전체 조회에서 3위였던 `정읍사 달빛 사랑숲`(실제 초승달)이
심볼 조회에서는 상위 3건에서 이탈했다. **잡으려던 대상을 오히려 놓쳤다.**

### 원인 — 조건이 비대칭이다

```
쿼리    : 심볼만 (크롭함)
상표 DB : 도형 + 글자 (전체 이미지)
```

쿼리만 자르고 상표는 자르지 않았다. `docs/api/ai-api.md` 실험 2가 지적한
"심볼 단독 쿼리는 레이아웃 불일치로 오탐" 문제와 같은 구조다. 크롭한
심볼이든 원래 심볼이든, DB 입장에서는 똑같이 "글자 없는 이미지"다.

### 근본 해결 (미착수)

상표 측도 동일하게 크롭한 **심볼 전용 인덱스**를 별도로 구축해야 조건이
대칭이 된다.

```
인덱스 A (기존)  상표 전체        <- 쿼리: 로고 전체    "전반적 인상"
인덱스 B (신규)  상표 심볼만 크롭  <- 쿼리: 심볼만 크롭  "도형 유사도"
```

두 점수를 함께 제시하면 의미가 갈린다. 상표 심사 관점에서는 B가 더 중요하다.

**선행 조건**
- 상표 7,423건 크롭 + 임베딩 재생성 (API 비용 없음, 로컬 연산)
- 상표 도면은 글자 위치가 제각각이라, 생성 로고만큼 단순한 크롭 규칙을
  쓸 수 없다. 도면 유형별 규칙 수립이 필요하다

## 처리 순서 제안

1. `app/` 프롬프트 이관 완료 (brief_service + prompt_service)
2. 확정 파이프라인으로 30장 생성 후 **앵커 재보정** — 1번 항목
3. 심볼 전용 인덱스 구축 검토 — 2·3번 항목

2번까지는 기존 구조 안에서 처리되고, 3번은 인덱스가 하나 더 늘어나므로
API 응답 스키마와 프론트 표시 방식까지 함께 논의해야 한다.
