## 1. OpenRouter 전환분과 브랜드킷 작업 병합 `9b4bb2a`

혜리씨의 `d0a9b45`(NVIDIA → OpenRouter flux.2-pro 전환)와 제 재생성 작업이
`flux_service.py`에서 충돌했습니다. **OpenRouter 호출부(`_call_flux_pro`)는 그대로 두고**
그 위에 `generate_logo_variants(variant_offset=...)`만 얹는 방식으로 합쳤습니다.

### `survey["_motif_jitter"]` 를 제거했습니다

```python
survey["_motif_jitter"] = random.randint(0, 1_000_000)   # ← 삭제
```

확인해 보니 **이 값을 읽는 코드가 어디에도 없습니다.** 모티프는
`prompt_service._resolve_motif`가 `variant_index`로만 선택하고 있어서,
이 줄은 실제로 아무 동작도 하지 않고 있었습니다.

시안 다양성을 확보하려는 의도로 보이는데, 그 역할은 재생성용으로 추가한
`variant_offset`이 담당합니다 (1회차 0~3 → 2회차 4~7로 모티프가 순환).
다른 의도가 있으셨다면 알려주세요.

### `seed`는 살아 있습니다

제가 한때 "OpenRouter로 바뀌면서 시드가 없어졌다"고 잘못 판단했는데, 확인 결과
**OpenRouter Image API는 seed를 지원합니다.**

```
GET /api/v1/images/models/black-forest-labs/flux.2-pro/endpoints
→ supported_parameters: { seed: {...}, aspect_ratio: {...}, output_format: {...} }
```

요청에 실어 보내고 응답으로도 돌려주도록 복원했습니다.

## 2. 프롬프트 조립 버그 4건 `dac9735`

### ① 모티프가 프롬프트에 들어가지 않고 있었습니다 (가장 큰 건)

모티프 카테고리를 고르지 않으면(= 실사용의 대부분) 이 문장으로 떨어졌습니다.

> drawn as ... in **an original brand-specific subject derived from the survey**

모델은 설문을 볼 수 없으므로, 사실상 **형태 지시가 없는 것과 같습니다.**
시안 4장이 모두 비슷한 추상 도형으로 수렴하던 주된 원인이었습니다.

뷰티 업종은 `MOTIF_MAP["뷰티"]`의 구체 모티프 16종(잎사귀·물방울·꽃잎·초승달·
조개나선 등)을 브랜드명 + `variant_index`로 순환 배정하도록 연결했습니다.

> **창수씨께**: `94062ed`에서 열린 지시로 바꾸신 판단과 그 테스트
> (`test_default_variants_do_not_force_fixed_fallback_shapes`)를 확인했습니다.
> **'기타' 업종은 손대지 않았습니다.** `MOTIF_MAP["기타"]`는 별·무한대·링처럼
> 상투적인 도형뿐이라 강제하면 오히려 밋밋해진다는 판단에 동의합니다.
> 뷰티 풀은 업종 특화 모티프라 강제해도 괜찮다고 보고 그쪽만 되살렸습니다.

### ② 색상을 HEX 코드 그대로 넘기고 있었습니다

```
전: in a #4F46E5 and #EC4899 color palette
후: in an indigo blue and vivid pink color palette
```

텍스트 인코더는 헥사 코드를 색으로 해석하지 못합니다. **화면에서 고른 색이
사실상 무시되고 있었습니다.** 가장 가까운 색 이름으로 변환해 넣습니다.

### ③ 영문 프롬프트에 한글 조각 + 비문

```
전: ... rather than a sketch. 신뢰, 혁신 The overall style references ...
전: The design has a friendly ... soft shapes character,
전: in a indigo blue color palette
```

서술형 가치 입력이 문장 없이 그대로 박혔습니다. 사전에 있는 키워드만 영어로
바꾸고 나머지 한글은 버립니다. 톤 문구 뒤 `character` 비문과 관사(a/an) 오류도
함께 고쳤습니다.

### ④ 프롬프트 길이 예산 800자

`NVIDIA_PROMPT_MAX_LEN = 800`은 NVIDIA Build 엔드포인트의 제한이었는데
(초과 시 422), OpenRouter로 옮긴 뒤에도 남아 톤·미학·가치 설명이 조용히
잘려나가고 있었습니다. `PROMPT_MAX_LEN`(기본 1400)으로 이름과 값을 정리하고
환경변수로 조정 가능하게 했습니다.

## 3. 타이포그래피 강화 `b91a0b2` ← 변경 폭이 가장 큽니다

### 왜 손댔는가

2026 뷰티 브랜딩 트렌드를 조사했더니 **"타이포그래피 우선"** 이 핵심으로 나왔습니다.
The Ordinary, Rhode, Milk Makeup 등 지금 잘나가는 브랜드는 대부분 **심볼이 없는
워드마크**이고, 브랜드명 글자 자체가 아이덴티티입니다.

우리 파이프라인은 심볼을 만들고 글자를 기계적으로 붙이는 구조라, 트렌드의
주인공을 부속품으로 다루고 있었습니다. 한글 렌더링 한계 때문에 구조 자체를
바꾸긴 어려우니, **폰트와 배치를 제대로 다루는 쪽**으로 개선했습니다.

### 폰트 6종 → 15종

| 추가 | 성격 |
|---|---|
| Pretendard Light / Thin | 얇은 산세리프 |
| IBM Plex Sans KR Light / Regular | 모던 지오메트릭 |
| Gowun Batang (고운바탕) Regular / Bold | 우아한 세리프 |
| Noto Serif KR Light / Regular | 정통 세리프 |
| Hahmlet Light / Regular | 모던 세리프 |

**전부 OFL(SIL Open Font License)입니다.** 무료 상업용 폰트 중에도 CI·BI 제작을
금지하는 것이 많은데(배민체·지마켓산스 등 기업 배포 폰트에 그런 조항이 있습니다),
우리는 문자 그대로 CI/BI를 만드는 서비스라 **OFL만 골랐습니다.**
라이선스 원문은 `app/fonts/licenses/`에 함께 넣었습니다.

### `light` 웨이트 풀 신설

기존 `_FONT_CANDIDATES`에는 `bold`/`regular`만 있었습니다.
**"얇은 글자 + 넓은 자간"이라는 프리미엄 워드마크의 기본 인상 자체를
만들 수 없는 상태**였습니다. `light` 키를 추가했고, light 폰트가 없는 환경에서도
regular로 자연스럽게 내려가도록 폴백을 넣었습니다.

### 글자 크기 기준: 심볼 바운딩박스 → 캔버스 폭

```python
전: font_size = max(14, round(symbol_h * 0.17))    # 심볼 bbox 높이 기준
후: font_size = max(14, round(width * 0.115))      # 캔버스 폭 기준
```

심볼이 항상 캔버스를 꽉 채우던 시절에는 문제가 없었지만, 여백을 둔 마크가
들어오면서 브랜드명이 같이 쪼그라들었습니다. 같은 4시안 안에서 실측한 값입니다.

| 시안 | symbol_h | 옛 공식 | 새 공식 |
|---|---|---|---|
| 1 | 611 | 104px | 118px |
| 2 | 495 | **84px** | 118px |
| 3 | 531 | 90px | 118px |
| 4 | 740 | **126px** | 118px |
| **편차** | | **42px** | **0** |

84px와 126px면 1.5배 차이입니다.

### 자간 상한 0.2em → 0.45em

프리미엄 뷰티 워드마크는 `L U N E R I A` 처럼 글자를 넓게 벌려 여백으로 격을
만듭니다. 기존 상한으로는 그 인상이 나오지 않았습니다.
톤별 (굵기, 자간) 조합 목록 `TONE_TEXT_STYLES`를 신설했습니다.

### 폰트·자간 선택을 무작위 → `variant_index` 순환

```python
전: return random.choice(candidates)
후: return candidates[variant_index % len(candidates)]
```

같은 설문을 두 번 돌리면 다른 폰트가 나와 결과를 재현할 수 없었습니다.
이제 **같은 설문이면 같은 결과**가 나오고, 시안 간에는 서로 다른 조합이
배정됩니다. 라우트(`generation.py`)와 스모크 스크립트에서 시안 순번을
넘기도록 연결했습니다.

`warm` 톤 4시안 배정 예시입니다.

| 시안 | 굵기 | 자간 | 폰트 |
|---|---|---|---|
| 1 | light | 0.40em | Noto Serif KR Light |
| 2 | regular | 0.28em | Noto Serif KR |
| 3 | light | 0.30em | Pretendard Light |
| 4 | regular | 0.18em | IBM Plex Sans KR |

## 4. 실험 도구 `2722fb6` `425359f` `8fa8ff6`

`prompt_service.py`를 건드리지 않고 다른 프롬프트를 시험할 수 있는 스크립트입니다.

```bash
cd ai-server
python scripts/try_logo.py 4 --dry          # 프롬프트만 출력 (무료)
python scripts/try_logo.py 4 --dry --v2     # 실험 프롬프트 v2 (무료)
python scripts/try_logo.py 4 --v2           # v2로 실제 생성
python scripts/try_logo.py 4 --v2 --tone warm
python scripts/try_similarity.py            # v1·v2 결과 유사도 일괄 검사
```

- 요청 전에 **실제로 모델에 들어가는 프롬프트 전문**을 출력합니다
- 지원하지 않는 톤·모티프를 넣으면 경고합니다 (기존에는 조용히 기본값으로 떨어졌습니다)
- 결과 파일명에 톤이 들어가 조합별 결과가 서로 덮어써지지 않습니다
- v2 구현은 `scripts/experimental_prompt.py`에 있고, **`app/` 어디서도 참조하지 않습니다**

비교 결과는 **`docs/prompt_v1_v2_비교.png`** 에 16장(2개 톤 × v1/v2 × 4시안)으로
정리해 두었습니다.

## 혜리씨 판단이 필요한 것 2가지

### ① 프롬프트의 조형 지시 방향

`prompt_service.py`의 `core`(547~561줄)에 이 문구들이 고정돼 있습니다.

```
A minimalist flat vector logo icon ...
drawn as one bold, large, solid-filled silhouette ...
with a thick, clean, unbroken outline that fills the canvas ...
flat 2D, with no gradients, shadows, or 3D rendering
```

klein 4B를 4스텝으로 돌리던 시절 "선이 끊긴다 / 도형이 너무 작다"를 막으려던
대처로 보입니다(주석에 그렇게 적혀 있습니다). **flux.2-pro에는 그 문제가 없어서,
지금은 품질 상한선으로만 작동하는 것 같습니다.**

실제로 같은 모델·같은 키로 손으로 쓴 프롬프트(`fine ornamental line art`)를 넣으면
가는 선의 정교한 로고가 나옵니다. 실험 스크립트의 v2는 이 세 지시를 톤에서
파생되는 값으로 바꾼 것인데, 결과가 확연히 다릅니다.

**비교 이미지 보시고 판단 부탁드립니다.**

### ② 심볼에 글자가 그려지는 문제

방금 4장 생성했는데 **1장에 `BEAUTY & N` / `Nd COSMETICS`가 그려져 나왔습니다.**
프롬프트에 이렇게 명시했는데도 무시됐습니다.

> Do not draw any letters, words, numbers, or typography of any kind —
> the brand name is added separately afterwards.

디퓨전 모델이 부정문을 잘 따르지 않는 전형적인 사례로 보입니다. v1에서
심볼 안에 `G`가 박혔던 것과 같은 뿌리인데, v2에서 확률이 낮아졌을 뿐
없어지지는 않았습니다.

**실제 서비스에서는 그대로 사용자에게 나가서 못 쓰는 시안이 됩니다.**
브랜드명이 "젠마크"인데 로고에 "BEAUTY & N COSMETICS"가 박혀 있으면 곤란합니다.

대응 방향은 둘로 보입니다.

1. **프롬프트** — 부정문을 긍정문으로 (`a purely pictorial mark composed only of shapes`).
   확률은 낮출 수 있지만 완전히 막지는 못합니다.
2. **생성 후 검출** — 합성 전에 심볼에 글자가 있는지 검사해 있으면 재생성.
   확실하지만 구현·비용이 듭니다.

현재 4장 중 1장(25%)이지만 표본이 작아 실제 발생률은 모릅니다.
어떻게 보시는지 의견 부탁드립니다.
