# Recraft 로고 생성 팀별 연동 명세

> 기준 브랜치: `develop`  
> 기준 커밋: `6084394`  
> 목적: 로고 생성 입력값이 Frontend → Backend → AI → Recraft까지 빠짐없이 전달되고, 선택한 색상과 로고 옵션이 최종 결과에 반영되도록 팀별 책임과 계약을 확정한다.

## 1. 결론

현재 문제는 한 팀만의 문제가 아니다.

| 문제 | 담당 영역 |
|---|---|
| 선택한 HEX 색상이 정확히 반영되지 않음 | AI 프롬프트·SVG 후처리 |
| `includeBrandName`, 모티프, 구체성 값이 끝까지 전달되지 않음 | Frontend ↔ Backend ↔ AI 계약 |
| 검은 사각형 배경이 남음 | AI SVG 배경 제거 |
| 브랜드명 배치가 어색함 | AI 텍스트 합성 |
| `후보 1~4`, `GENMARK AI` 표시 | Frontend 고정 UI 문구 |
| 실제 모델은 Recraft인데 생성 이력에 Flux로 기록됨 | Backend 메타데이터 |
| Recraft 원본 SVG가 Backend에서 유실됨 | Backend 응답 파싱·저장 |

핵심 원칙:

1. Frontend가 선택값을 명확한 필드로 보낸다.
2. Backend는 프로젝트에 저장한 뒤 같은 의미의 snake_case 필드로 AI 서버에 전달한다.
3. AI 서버는 HEX를 일반 색상명으로 대체하지 않는다.
4. 정확한 색상은 프롬프트에만 맡기지 않고 SVG 후처리로 보장한다.
5. 후보 번호 등 화면용 문구는 로고 이미지 안에 포함하지 않는다.

## 2. 현재 흐름(AS-IS)

```text
Frontend colors[]
→ Backend color1, color2, color3, color4
→ AI color_manual[]
→ AI가 HEX를 pink, sky blue 같은 색상명으로 변환
→ Recraft에 prompt 문자열 하나로 전달
→ Recraft SVG
→ AI가 PNG 변환 + 브랜드명 합성
→ Backend가 PNG만 저장하고 SVG는 버림
→ Frontend가 storageKey로 PNG 표시
```

현재 Recraft/OpenRouter 요청은 아래 세 필드뿐이다.

```json
{
  "model": "recraft/recraft-v4-vector",
  "prompt": "설문 내용을 합친 영어 프롬프트",
  "aspect_ratio": "1:1"
}
```

색상, 톤, 모티프는 별도 Recraft 파라미터가 아니라 `prompt` 문자열 안에 포함된다.

## 3. 공통 필드 계약(TO-BE)

| 의미 | Frontend | Backend 저장/DTO | AI 요청 | 필수 여부 |
|---|---|---|---|---|
| CI/BI 구분 | `brandType` | 프로젝트 종류 | `ci_bi` | 필수 |
| 브랜드명 | `brandName` | `brandName` | `brand_name` | BI 필수 |
| 회사명 | `companyName` | `companyName` | `company_name` | CI 필수 |
| 업종 | `industry` | `industry` | `industry` | 필수 |
| 브랜드 가치 | `brandValues` | `valueCategory1~3` | `brand_values` | 선택 |
| 설명 | `brandValuesText` | `brandDescription/coreValues` | `brand_values_text` 또는 `company_values_text` | 선택 |
| 타깃 연령 | `targetAge` | `targetAge` | `target_age` | BI 선택 |
| 분위기 | `tone` | `tone` | `tone` | 필수 |
| 색상 모드 | `colorMode` | `colorMode` | `color_mode` | 필수 |
| 선택 색상 | `colors[]` | `color1~4` | `color_manual[]` | 수동 선택 시 필수 |
| 로고 유형 | `logoStyle` | `logoStyle` | `style` | 필수 |
| 브랜드명 포함 | `includeBrandName` | `includeBrandName` | `include_brand_name_in_logo` | 필수 |
| 모티프 카테고리 | `motifCategories[]` | `motifCategories` | `motif_category[]` | 선택 |
| 구체성 | `concreteness` | `concreteness` | `concreteness` | 선택 |
| 추가 요구사항 | `additionalRequirements` | `additionalRequirements` | `additional_requirements` | 선택 |
| 후보 수 | 화면 고정값 4 | 생성 정책 4 | `num_variants: 4` | 필수 |
| 재생성 위치 | 내부값 | 이전 생성 기준 계산 | `variant_offset` | 재생성 시 필수 |

### 허용값

```text
colorMode: MANUAL | TONE
logoStyle: symbol | wordmark | combination | lettermark
includeBrandName: true | false
colors: #RRGGBB 형식, 1~4개
numVariants: 기본 4, 최대 8
```

Backend가 AI 서버로 보낼 때는 현재 AI 스키마에 맞게 다음 값을 사용한다.

```text
MANUAL → color_mode: "manual"
TONE   → color_mode: "ai"
symbol      → style: "심볼"
wordmark    → style: "워드마크"
combination → style: "혼합형"
lettermark  → style: "레터마크"
```

## 4. Frontend 팀 전달사항

### 현재 확인된 상태

- `colors[]`는 `color1~4`로 변환되어 Backend에 전달된다.
- `colorMode`와 `includeBrandName`은 Frontend 상태에는 있지만 Backend 요청 DTO에 끝까지 반영되지 않는다.
- `후보 1~4`, `GENMARK AI`는 `App.tsx`의 화면용 고정 문구다.

### 구현 요청

1. 프로젝트 저장 요청에 아래 값을 누락 없이 포함한다.

```ts
{
  colorMode: 'MANUAL' | 'TONE',
  color1?: '#RRGGBB',
  color2?: '#RRGGBB',
  color3?: '#RRGGBB',
  color4?: '#RRGGBB',
  includeBrandName: boolean,
  motifCategories?: string[],
  concreteness?: string,
  logoStyle: 'symbol' | 'wordmark' | 'combination' | 'lettermark',
  additionalRequirements?: string
}
```

2. 수동 색상 선택 시 최소 한 색 이상을 검증한다.
3. 전송 직전 HEX는 대문자 `#RRGGBB` 형식으로 정규화한다.
4. `후보 1~4`, `GENMARK AI`는 이미지와 분리된 UI 라벨로 유지한다.
5. API 응답의 `modelName`을 화면 또는 디버그 정보에서 확인할 수 있게 한다.

### Frontend 완료 조건

- 브라우저 Network 요청에서 선택한 HEX가 `color1~4`로 그대로 보인다.
- 브랜드명 포함 여부, 모티프, 구체성이 요청 JSON에 존재한다.
- 로고 PNG 안에는 `후보 1`, `GENMARK AI`가 들어가지 않는다.

## 5. Backend 팀 전달사항

### 현재 확인된 상태

- `color1~4` 저장과 `color_manual[]` 전달은 동작한다.
- `color_mode`는 현재 항상 `MANUAL`로 만들어진다.
- 생성 이력의 `modelName`이 `black-forest-labs/flux.2-klein-4b`로 하드코딩되어 있다.
- AI 응답의 `svg`는 파싱하지 않고 버린다.

### 구현 요청

1. CI/BI 프로젝트 요청 DTO와 Entity에 다음 값을 추가·보존한다.

```text
colorMode
includeBrandName
motifCategories
concreteness
```

2. `toSurvey()`가 공통 필드 계약의 snake_case 값으로 변환하도록 한다.
3. 생성 이력 `modelName`은 최소한 아래 값으로 실제 설정과 일치시킨다.

```text
recraft/recraft-v4-vector
```

가능하면 AI 서버 응답 또는 환경설정에서 모델명을 받아 기록하여 재하드코딩을 막는다.

4. `FastApiLogoAiClient.GeneratedLogo`가 다음 응답을 모두 파싱하도록 한다.

```json
{
  "imageBase64": "최종 PNG Base64",
  "svg": "Recraft SVG 원본",
  "seed": null,
  "variantIndex": 0
}
```

5. PNG는 기존처럼 화면 표시용으로 저장하고, SVG는 다운로드·편집용으로 별도 보존한다.
6. 새 DB 컬럼이 필요하면 migration과 `database/schema.sql`을 함께 갱신한다.

### Backend 완료 조건

- 생성 직전 `request_snapshot_json`에서 선택한 HEX와 옵션을 확인할 수 있다.
- AI 서버 요청 JSON에 `color_manual`, `include_brand_name_in_logo`, `motif_category`, `concreteness`가 존재한다.
- 생성 이력의 `modelName`이 Recraft로 기록된다.
- AI가 반환한 SVG가 유실되지 않는다.

## 6. AI 팀 전달사항

### 현재 확인된 상태

- 모델은 `recraft/recraft-v4-vector`다.
- HEX를 가까운 일반 색상명으로 변환한 뒤 프롬프트에 넣는다.
- Recraft SVG를 PNG로 변환하고 브랜드명은 Pillow로 별도 합성한다.
- SVG 배경 제거가 완전하지 않아 검은 사각형이 남을 수 있다.

### 구현 요청

1. HEX를 색상명으로 대체하지 않는다. 프롬프트에 색상명과 정확한 HEX를 함께 명시한다.

```text
Use #EF5B7A as the primary color and #75ADD2 as the accent color.
Do not introduce black, white fills, or any unrequested colors except transparency.
```

2. 프롬프트만으로 정확한 색을 보장하지 않는다. Recraft SVG 응답 후 `fill`과 `stroke`를 선택 팔레트로 정규화한다.
3. 첫 번째 색상은 primary, 두 번째 이후는 accent 순서로 취급한다.
4. 배경은 투명으로 보장한다. 캔버스 전체를 덮는 배경 도형만 제거하고 실제 심볼 도형은 제거하지 않는다.
5. `include_brand_name_in_logo` 처리 기준을 통일한다.

```text
false → 심볼만 반환
true  → Recraft 심볼 + 서버 텍스트 합성
wordmark/lettermark → 심볼 생성 없이 텍스트 중심 합성
```

6. 최종 응답에 실제 모델명을 포함하는 것을 권장한다.

```json
{
  "model": "recraft/recraft-v4-vector",
  "logos": [
    {
      "imageBase64": "...",
      "svg": "<svg ...>",
      "seed": null,
      "variantIndex": 0
    }
  ]
}
```

7. 로그에는 키를 노출하지 않고 다음만 남긴다.

```text
model
variantIndex
color palette
prompt hash 또는 request id
Recraft 응답 시간
SVG 후처리 성공/실패
```

### AI 완료 조건

- 선택한 HEX가 최종 SVG `fill` 또는 `stroke`에 정확히 존재한다.
- 요청하지 않은 검은 배경이 없다.
- PNG 배경 alpha가 투명하다.
- `include_brand_name_in_logo=false`일 때 브랜드명 텍스트가 없다.
- 같은 요청의 후보 4개는 모티프가 서로 구분된다.

## 8. 통합 검증 시나리오

다음 입력으로 한 번의 E2E 검증을 수행한다.

```text
브랜드명: 서성찬
색상: #EF5B7A, #75ADD2
로고 유형: 혼합형
브랜드명 포함: true
모티프: 기하학적 도형
구체성: 적당히 단순화
```

팀 공동 확인 항목:

- [ ] Frontend Network 요청에 모든 입력값이 존재한다.
- [ ] Backend DB와 `request_snapshot_json`에 값이 보존된다.
- [ ] Backend → AI JSON에서 HEX가 변형되지 않는다.
- [ ] AI가 만든 최종 프롬프트에 두 HEX가 모두 존재한다.
- [ ] Recraft 호출 모델이 `recraft/recraft-v4-vector`다.
- [ ] 최종 SVG에 선택한 HEX가 존재한다.
- [ ] 검은 사각형 배경이 없다.
- [ ] PNG와 SVG 다운로드가 가능하다.
- [ ] 이미지 안에는 후보 번호나 `GENMARK AI`가 없다.
- [ ] 후보 4개가 서로 다른 형태다.

## 9. 권장 작업 순서

1. Backend: 공통 DTO·저장 필드·AI 요청 계약 확정
2. Frontend: 누락 필드 전송 및 Network 검증
3. AI: 정확한 HEX 유지, SVG 팔레트 정규화, 배경 제거 수정
4. Backend: SVG 보존과 실제 모델명 기록
5. 세 팀 공동 E2E 검증

각 단계는 별도 commit으로 나누고, 다음 단계로 넘어가기 전에 위 통합 체크리스트의 해당 항목을 확인한다.
